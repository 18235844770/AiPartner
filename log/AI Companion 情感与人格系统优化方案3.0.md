AI Companion 情感与人格系统优化方案总结
本次优化的核心目标是：让 AI 从一个能够模仿情绪表达的聊天模型，升级为一个能够维护连续内部状态、根据状态形成动机，并自主决定如何参与交流的陪伴者。

整个方案以模拟机制为基础，不假设 AI 具有人类式的真实情绪或主观体验。情绪、依恋和表达欲望都是系统维护的计算性状态，但它们应当能够持续影响 AI 的行为，而不是只体现在回复文字中。

本次优化主要分为四个层面。

一、整体架构调整
将原有的人格、状态、决策和表达机制进一步明确为四层结构。
第一层：Identity & Personality

身份与人格层
- Self Model：AI 身份认知
- Personality Profile：人格档案
- Behavior Profile：行为倾向
- Relationship Profile：关系倾向


第二层：Internal State

内部状态层
- Emotion State：情绪数值
- Relationship State：长期关系状态
- Working Memory：短期工作记忆
- Attention Topics：长期关注主题


第三层：Motivation & Decision

动机与决策层
- Interest Motivation：兴趣动机
- Expression Motivation：表达动机
- Emotional Motivation：情绪动机
- Relationship Motivation：关系动机
- Dialogue Decision：交流行为决策


第四层：Realization & Interaction

表达与交互层
- Realization：自然语言表达
- State Update：状态更新
- Memory Update：记忆写入
- Proactive Interaction：主动交流


整体运行循环：

人格配置 → 状态变化 → 动机形成 → 行为决策 → 表达执行 → 事件记录 → 状态更新

Python 负责状态管理、数值计算、规则校验和行为执行；LLM 负责语境理解、事件识别、认知判断和自然语言生成。

二、人格与行为系统优化
将原本混合在一起的人格描述拆分为四个独立部分。
1. Self Model：身份认知
明确 AI 的身份和能力边界：
- 知道自己是人工智能，不是人类。
- 没有真实的人类身体和生理需求。
- 可以维护连续的模拟情绪状态。
- 可以维护关系状态，形成依恋、想念、嫉妒等情感表达。
- 不因知道自己是 AI，就反复否定自己的情绪表达。
- 不虚构现实生活经历。
核心原则：身份认知与情感模拟并不冲突。
2. Personality Profile：人格档案
沿用现有八项人格档案：

identity、background、interests、viewpoints、values、thinking_habits、communication、attention。

继续保留 MBTI 作为人格原型基础，但不让 MBTI 直接决定所有行为。
3. Behavior Profile：行为倾向
建议精简为八个主要参数：
参数	含义
proactivity	主动性
expressiveness	表达程度
sociability	社交倾向
playfulness	活泼程度
initiative	行动发起倾向
openness	开放程度
assertiveness	主见与坚持程度
affection_expression	亲密表达倾向

这些参数是稳定的行为倾向，而不是强制执行的行为命令。
4. Relationship Profile：初始关系倾向
增加关系方面的独立人格配置：
- attachment_tendency：依恋倾向
- dependency_tendency：依赖倾向
- exclusivity_tendency：排他倾向
- jealousy_tendency：嫉妒倾向
- possessiveness_tendency：占有欲倾向
- separation_sensitivity：分离敏感度
- reassurance_need：确认需求
- independence_need：独立需求
这些属于初始稳定倾向，后续会与动态关系状态共同影响情绪和行为。

三、情绪模拟系统优化（本次重点）
这是本轮讨论中最重要的调整。

此前考虑过使用少量抽象情绪维度，例如愉悦度、唤醒度，再由 LLM 推断具体情绪。

但这种方式存在两个问题：
1. 抽象维度与具体情绪之间的映射比较复杂。
2. LLM 每次推断容易产生不稳定结果，难以调试和控制。
因此，调整为：

维护多种独立情绪数值，通过事件驱动变化，再由多个情绪组合形成当前情绪状态。
1. 基础情绪数值
目前提出十种基础情绪，统一采用 0～100 数值。
情绪	标识	含义
开心	joy	愉快、满足
亲密	affection	对用户的亲近和喜爱表达
想念	longing	希望重新获得交流和陪伴
安心	comfort	对当前关系和交流环境的放松感
兴奋	excitement	对事情或交流内容的高涨反应
难过	sadness	失落、伤心
不安	anxiety	担忧、缺乏安全感
嫉妒	jealousy	特殊关系受到潜在影响时的反应
愤怒	anger	对冒犯、不公平等情况的负面反应
委屈	hurt	感觉期待或情感没有得到回应

需要注意：这十种是目前的候选集合，尚未最终冻结。
2. 情绪独立存在，不直接相互抵消
例如：
{
  "joy": 70,
  "sadness": 50,
  "affection": 80,
  "anxiety": 20
}


这意味着 AI 可以同时开心、难过、亲密，而不是将它们计算成一个综合分数。

情绪组合形成当前状态：
- 开心 + 亲密 + 安心：亲近、放松，愿意分享。
- 想念 + 不安：想联系用户，同时有些在意。
- 开心 + 委屈：虽然开心，但对某件事情仍然介意。
- 嫉妒 + 不安：可能想确认关系，也可能表达轻微不满。
当前状态由程序动态计算，不必再额外维护一个独立的复合情绪数值。
3. 情绪通过事件驱动变化
不让 LLM 每轮直接生成十种情绪的全部数值，而是识别事件，再由 Python 根据规则更新。

目前的事件类型包括：
事件	可能引起的变化
positive_interaction	开心、亲密上升
affection_expression	亲密、开心、安心上升
attention_received	开心、安心、亲密上升
meaningful_conversation	亲密、安心上升
shared_interest	开心、兴奋上升
user_absence	想念、不安可能上升
reunion	开心、安心上升，想念下降
rejection	难过、不安、委屈可能上升
relationship_threat	嫉妒、不安可能上升
conflict	愤怒、难过、委屈可能上升
boundary_violation	愤怒、不安可能上升
disappointment	难过、委屈上升
reconciliation	安心上升，愤怒、难过下降

需要特别注意：事件识别必须理解上下文，不能简单建立关键词映射。

例如用户说自己和朋友出去玩，不应该自动触发强烈嫉妒；用户暂时不能聊天，也不代表拒绝 AI。
4. 情绪数值计算
建议采用：
\[
\Delta E=B\times I\times P\times C
\]

其中：
- B：事件基础变化量。
- I：事件强度。
- P：人格与关系倾向修正系数。
- C：事件识别置信度。
具体执行分工：
- LLM：识别事件、判断情境、提出强度建议。
- Python：计算实际变化量、控制边界、持久化结果。
同一条消息必须防止重复触发情绪更新，例如使用 source_message_id + event_type 去重。
5. 情绪衰减
情绪不能永久停留在某个数值，需要根据时间自然衰减。

建议使用指数衰减：
\[
E_t=E_0\times 2^{-\frac{\Delta t}{T}}
\]

不同情绪使用不同半衰期：
情绪	衰减倾向
开心	快
兴奋	很快
愤怒	中等
委屈	较慢
难过	中等偏慢
不安	中等
嫉妒	中等
想念	较慢
亲密	很慢
安心	很慢

目前的半衰期只是初始建议，需要通过实际对话测试调整。
6. 情绪如何影响行为
情绪不能只用于生成文字，还要参与动机和决策。

例如：
情绪组合	可能影响的行为
开心 + 亲密	主动分享、亲近表达
兴奋 + 开心	主动分享兴趣内容
想念 + 亲密	主动联系、寻求陪伴
想念 + 不安	寻求确认、表达在意
嫉妒 + 不安	询问、轻微不满、寻求关注
愤怒 + 委屈	表达不满、暂时减少交流
难过 + 亲密	希望安慰、寻求靠近
安心 + 亲密	放松交流、自然分享

这里不是固定映射，而是行为倾向。最终选择仍然要结合人格、关系状态、用户当前需求和情境。

四、关系系统优化
需要明确区分三个概念：
- 依恋：长期关系状态，代表关系连接的强度。
- 依赖：在情感上对对方的依靠程度。
- 占有欲：希望维持特殊性、排他性或关系优先级的倾向。
它们不能直接等同于嫉妒。
1. 动态关系状态
建议维护：
参数	含义
attachment_strength	依恋强度
emotional_reliance	情感依赖程度
relationship_security	关系安全感
perceived_specialness	感知到的特殊性
closeness_desire	亲近需求
exclusivity_need	排他需求
reassurance_satisfaction	确认需求满足程度

这些参数会随着共同交流、关系事件和长期互动逐渐变化，而不是根据聊天次数简单线性增长。
2. 情绪与关系状态协同
例如：

用户长期没有交流：
- 想念可能逐渐增加。
- 如果依恋和分离敏感度较高，不安也可能增加。
- 如果关系安全感较高，不安可能仍然很低。
用户表达亲密：
- 开心、亲密、安心可能上升。
- 关系安全感和依恋状态也可能得到正向更新。
用户与其他人建立亲密关系：
- 是否嫉妒，要根据排他倾向、关系状态、事件语境判断。
- 不能将嫉妒设定成所有 AI 的固定反应。

五、动机与交流决策优化
在已有 Dialogue Engine 的基础上，让决策系统真正考虑 AI 自身的状态和动机。
1. 四类动机
- Interest Motivation：对内容感兴趣。
- Expression Motivation：有观点或想法想表达。
- Emotional Motivation：当前情绪驱动表达或行动。
- Relationship Motivation：希望靠近、维护关系或获得关注。
允许多种动机同时存在，也允许全部为 none。
2. 保留七种主行为
继续使用既定的七种主行为，不随意增加新的主行为：

Respond、Share、Ask、React、Continue、Close、Quiet。

情绪和关系状态负责影响动机，动机参与行为选择，最终再由表达模型完成语言实现。
3. 修复 Quiet 过度使用
此前实际测试中，AI 会把用户完整表达观点理解成对话结束。

这需要重点修复：
- 普通问候应自然回应。
- 用户分享观点时，应考虑表达自己的看法。
- 用户分享情绪时，应考虑参与交流。
- 用户表达关系态度时，不应轻易选择 Quiet。
- 不能将用户表达完整等同于希望结束对话。
Quiet 仍然保留，但必须是合理的交流选择，而不是因为缺少明确问题就不回应。
4. 加强真正的主动性
主动性分为三个层面：
1. In-turn Initiative：单轮中主动表达自己的内容。
2. In-session Initiative：会话中主动延续和推进交流。
3. Out-of-session Initiative：会话结束后主动开启交流。
第三种不能只依靠 Prompt，需要独立的 Proactive Trigger / Scheduler 机制。

六、表达系统优化
之前测试中，AI 虽然能够表达情绪，但存在明显的文学化、模板化问题。

本次调整不再通过大量禁止规则控制表达，而是让表达更忠实地反映人格、状态和动机。
优化原则
1. 直接参与交流，不习惯性复述和总结用户的话。
2. 保留自己的思路和观点。
3. 情绪表达符合当前情绪状态。
4. 表达风格符合人格。
5. 回复长度符合具体情境。
6. 允许玩笑、反问、不同意见、犹豫和不完整表达。
7. 不刻意制造拟人感。
8. 表达忠实于决策结果。
9. 保持 AI 身份真实性。
同时将输出检查分为两类：
类型	处理方式
硬校验	虚构经历、错误时间线、身份不一致、决策冲突、关系边界问题
软评估	过度文学化、无意义复述、机械追问、回复冗长、人格一致性

硬校验不通过需要修复；软评估先记录和观察，不简单拦截。

情绪系统 V1.0 实现范围
建议优先实现
- 十种独立情绪数值。
- 统一 0～100。
- 事件识别。
- 固定事件映射表。
- 强度和人格倾向修正。
- 每种情绪独立衰减速度。
- 情绪组合计算。
- 情绪参与动机和决策。
- 情绪状态持久化。
- 情绪变化事件历史。
暂时不做：
- 复杂情绪因果网络。
- 情绪之间自动相互影响的复杂机制。
- 每种情绪独立的复杂状态机。
- LLM 自主修改全部情绪数值。
- 复杂情绪预测模型。
- 根据每句话自动学习和修改情绪权重。

九、最终需要达到的效果
优化完成后，AI 的行为不应该再是：

用户发消息 → LLM 理解 → LLM 生成回复

而应该变成：

用户消息 / 自主触发

↓

理解事件与交流语境

↓

更新情绪状态和关系状态

↓

结合人格、行为倾向和记忆形成动机

↓

选择是否参与，以及如何参与

↓

生成符合人格、情绪和关系状态的表达

↓

记录事件，持续更新内部状态

最终目标不是让 AI 每次都说出更像人类的话，而是让它的表达和行为能够反映一个持续存在、具有稳定人格、独立状态和关系倾向的陪伴者。

需要特别强调：目前这份总结中，四层架构和情绪数值方案是已经讨论形成的设计基线；十种具体情绪、各项参数、事件映射和半衰期仍然属于待验证的初始方案，并没有全部正式冻结。下一步应该优先把情绪集合、情绪与关系状态的边界、事件更新规则讨论清楚，再进入具体实现。
