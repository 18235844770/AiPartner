- ## 1. 系统定位与设计目标

  ### 1.1 系统定位

  Memory Engine（记忆引擎）是 AI Companion 的长期信息管理与认知基础设施。

  它不仅负责保存用户说过的话，还负责从长期交流中提取有价值的信息，建立用户认知、记录共同经历、维护长期关注主题，并在适当的时机将相关记忆提供给 Dialogue Engine。

  核心目标是让 AI 能够：

  - 记住用户的重要信息和共同经历。
  - 理解当前话题与过去交流之间的联系。
  - 随着交流深入逐渐形成对用户的认知。
  - 发现用户的变化，并修正之前的认知。
  - 主动回顾过去，而不是只被动回答历史问题。
  - 形成自己的长期关注主题，并在适当时机主动分享。

  ### 1.2 设计原则

  原则一：不是所有对话都需要成为长期记忆。

  完整保存对话记录，但只将有价值的信息提炼为长期记忆。避免记忆系统成为简单的聊天内容数据库。

  原则二：记忆必须能够持续演进。

  用户的偏好、目标、生活状态和关系都可能变化。系统需要允许补充、修正、变化和归档，而不是永久保留最初的判断。

  原则三：明确区分事实与认知。

  用户明确表达的信息属于事实记忆；AI 根据多次交流归纳出来的判断属于认知记忆。两者必须分开管理。

  原则四：记忆应当服务于交流。

  保存记忆不是最终目的。真正的价值在于能够在合适的交流场景中调用记忆，让 AI 的回应具有连续性和熟悉感。

  原则五：用户拥有记忆控制权。

  用户可以查看、纠正和删除记忆，也可以明确要求记住或不再记住某些内容。

  

  ## 2. 四层记忆架构

  Memory Engine 采用四层记忆架构。

  第四层：情景记忆 Episodic Memory

  重要事件、共同经历、关键决定、关系变化

  第三层：语义记忆 Semantic Memory

  稳定事实、偏好、习惯、目标、归纳认知

  第二层：工作记忆 Working Memory

  当前话题、近期上下文、未完成事项

  第一层：原始记录 Conversation Log

  完整对话、时间、发言者、会话记录

  由原始交流记录提供依据，经过提取、整理和关联形成更高层记忆。

  ### 2.1 原始记录层（Conversation Log）

  保存所有有效的对话原始记录。

  主要内容：

  - 用户发送的消息。
  - AI 发送的消息。
  - 消息时间。
  - 所属会话。
  - 消息来源和必要的附件信息。

  主要职责：

  1. 提供完整的历史对话依据。
  2. 为其他记忆提供来源追溯。
  3. 支持历史对话回顾。
  4. 在记忆提取错误时提供纠正依据。

  原始记录原则上采用追加式存储，不因为上层记忆发生变化而直接改写。

  ### 2.2 工作记忆层（Working Memory）

  保存当前交流和近期互动需要使用的信息。

  主要内容：

  - 当前讨论主题。
  - 当前话题的上下文摘要。
  - 最近交流中的重要信息。
  - 尚未完成的讨论事项。
  - 尚待跟进的问题。
  - 临时性信息。

  例如：

  用户正在讨论一个 AI 产品的架构设计，当前工作记忆需要保留：

  - 正在讨论哪个模块。
  - 已经确定哪些设计决策。
  - 哪些问题还没有讨论。
  - 当前讨论处于什么阶段。

  工作记忆的核心目的是保证当前交流连续性。

  会话结束后，可以将有价值的信息整理进入语义记忆或情景记忆，其余临时信息可以过期。

  ### 2.3 语义记忆层（Semantic Memory）

  语义记忆是长期了解用户的重要基础。

  主要保存：

  - 用户的基本背景。
  - 稳定偏好。
  - 长期兴趣。
  - 生活习惯。
  - 职业和学习方向。
  - 长期目标。
  - 持续进行的项目。
  - 经过多次交流形成的用户认知。

  语义记忆分为两种：

  A. 显式事实

  用户明确表达的信息。

  例如：

  - 用户从事前端开发。
  - 用户希望向 AI 领域转型。
  - 用户喜欢某种交流方式。

  B. 归纳认知

  AI 根据长期交流形成的判断。

  例如：

  - 用户在决策时更关注最终结果。
  - 用户喜欢通过挑战验证自身能力。
  - 用户倾向于先分析问题，再决定是否采取行动。

  归纳认知必须保留形成依据、置信度和适用范围。

  不能因为一次交流就将某种行为归纳为长期人格特征。

### 2.4 情景记忆层（Episodic Memory）

情景记忆用于记录具有明确时间和背景的重要事件。

主要内容：

- 重要的人生经历。
- 关键决定。
- 关系发展与变化。
- 重要的成功或失败。
- 项目阶段性成果。
- 特殊交流事件。
- 其他具有长期回顾价值的经历。

每条情景记忆应尽可能包含：

| 字段     | 说明                     |
| -------- | ------------------------ |
| 事件名称 | 对事件的简要描述         |
| 发生时间 | 事件发生时间             |
| 参与对象 | 涉及的人物               |
| 背景     | 事件发生的原因和环境     |
| 过程     | 关键发展过程             |
| 结果     | 最终发生了什么           |
| 用户态度 | 用户当时表达的感受或判断 |
| 后续变化 | 后续是否产生新的发展     |

情景记忆与语义记忆的区别：

- 情景记忆回答：过去发生过什么？
- 语义记忆回答：通过长期交流，我们能够形成什么稳定认知？



## 3. 记忆提取与写入机制

记忆系统不能只依赖模型在回复时临时回忆，而应当拥有独立的记忆处理流程。

### 3.1 处理流程





```flowchart TD
    A[收到一轮对话] --> B[保存原始对话]
    B --> C[异步提取候选信息]
    C --> D[记忆类型分类]
    D --> E[重要性与稳定性评估]
    E --> F[检索相关已有记忆]
    F --> G{写入决策}
    G -->|新增| H[创建记忆]
    G -->|补充| I[补充现有记忆]
    G -->|修正或变化| J[创建新版本]
    G -->|暂存| K[候选记忆池]
    G -->|无价值| L[不进入长期记忆]
    H --> M[建立来源与关联]
    I --> M
    J --> M
    K --> M
```



### 3.2 信息提取

每轮对话结束后，系统从消息中识别：

- 事实信息。
- 兴趣偏好。
- 行为习惯。
- 目标与计划。
- 重要事件。
- 人物关系。
- 观点和价值判断。
- 情绪及其背景。
- 未完成事项。
- 长期关注主题。

这里需要特别注意：

情绪本身通常不应该直接变成长期记忆，但如果某次情绪具有重要背景和长期意义，可以作为情景记忆的一部分保存。

### 3.3 重要性评估

采用多维评分辅助决定记忆是否值得长期保存。

初始评分公式：

\[ S=0.30I+0.25T+0.15R+0.20C+0.10F \]

其中：

| 指标 | 含义   |
| ---- | ------ |
| I    | 重要性 |
| T    | 稳定性 |
| R    | 重复性 |
| C    | 关联性 |
| F    | 时效性 |

每个指标取值为 0–1。

该公式只是初期辅助判断工具，不是不可调整的硬性规则。

例如：

- 用户明确要求记住的重要事项，可以直接进入正式记忆。
- 用户一次性提及的普通信息，可以暂时保存为候选记忆。
- 用户多次表达相同偏好，可以逐渐升级为稳定记忆。
- 用户偶尔表达的不满，不应直接变成长期性格判断。

### 3.4 记忆处理方式

系统支持五种处理结果：

1. 新增记忆。
2. 补充已有记忆。
3. 修正已有记忆。
4. 暂存候选记忆。
5. 忽略或归档。

整个流程采用异步处理，避免影响实时对话响应。

同时需要使用幂等标识，避免同一条消息重复处理后产生重复记忆。



## 4. 记忆生命周期

```flowchart TD
    A[候选记忆] --> B[暂存与评估]
    B --> C{是否达到保留条件}
    C -->|否| D[继续观察或过期]
    C -->|是| E[正式记忆]
    E --> F[检索与使用]
    F --> G{是否需要更新}
    G -->|补充| H[创建补充版本]
    G -->|修正或变化| I[创建新版本]
    G -->|暂不更新| F
    H --> F
    I --> F
    F --> J{是否仍有价值}
    J -->|是| F
    J -->|否| K[归档]
    E --> L[用户删除请求]
    K --> L
    L --> M[删除及派生数据清理]

```



### 4.1 候选记忆

刚刚提取的信息不一定直接成为长期记忆。

例如用户偶然提到喜欢某种食物，可以先作为候选信息。

### 4.2 正式记忆

达到重要性要求，或者属于明确要求保存的重要内容时，进入正式记忆。

### 4.3 记忆更新

正式记忆并不是永久固定的。

系统需要区分：

- 补充：原有信息仍然正确，只是增加了细节。
- 修正：之前的信息存在错误。
- 变化：用户的实际情况已经发生改变。
- 场景差异：不同环境下出现不同表现。

### 4.4 记忆归档

已经不再活跃的信息可以进入归档状态。

归档不代表删除，而是降低检索优先级。



## 5. 记忆版本与冲突处理

系统采用版本化更新，不直接覆盖历史信息。

建议使用以下字段：

| 字段                 | 说明                   |
| -------------------- | ---------------------- |
| version              | 当前版本               |
| valid_from           | 当前信息开始成立的时间 |
| valid_to             | 当前信息失效的时间     |
| supersedes_memory_id | 被替代的旧记忆         |
| source_message_ids   | 信息来源               |
| change_reason        | 更新原因               |

例如：

用户过去喜欢某种交流方式，后来明确表示已经不再喜欢。

系统应该：

1. 保留过去的偏好记录。
2. 将过去偏好的有效期结束。
3. 创建当前的新偏好。
4. 记录变化发生的时间。
5. 在未来检索时优先使用当前有效版本。

如果新旧信息无法判断谁正确，则保留冲突状态，不擅自覆盖。



## 6. 用户认知形成机制

已确认：适度归纳

这是 Memory Engine 中非常重要的部分。

AI 不应该只是一个信息记录器，还需要在长期交流中逐渐形成对用户的理解。

### 6.1 认知来源

认知可以来自：

- 多次相似行为。
- 不同场景中的相似决策。
- 用户反复表达的观点。
- 用户在长期项目中的表现。
- 用户明确确认的自我描述。
- 多个事件之间存在的共同规律。

### 6.2 置信度机制

每条归纳认知都需要置信度。

| 等级 | 判断依据                             |
| ---- | ------------------------------------ |
| 低   | 单次观察，或证据有限                 |
| 中   | 多次相似表现                         |
| 高   | 用户明确确认，或长期、多场景证据充分 |

置信度不是永久不变的。

新证据出现时，需要重新评估。

### 6.3 认知与事实分离

例如：

用户明确说：

“我喜欢独立完成工作。”

这是显式事实。

AI 根据多次交流形成：

“用户在面对复杂任务时，通常更倾向于自己掌握决策权。”

这是归纳认知。

系统不能将第二种信息记录成用户曾经明确说过的话。

### 6.4 认知修正

当新行为与旧认知冲突时：

1. 检查是否存在场景差异。
2. 检查用户是否发生变化。
3. 检查之前的判断是否过度归纳。
4. 评估新证据是否足够。
5. 必要时降低置信度或创建新认知。

未被用户反驳，不等于用户认可。



## 7. 主动表达认知

已确认：允许主动表达

AI 可以主动表达自己对用户的观察和理解，而不是只在用户询问时才调用记忆。

### 7.1 触发条件

- 新信息与已有认知产生有价值的联系。
- 发现用户某种行为模式发生变化。
- 当前话题自然涉及过去的经历。
- 发现以前的认知可能存在偏差。
- 当前交流适合表达理解。

### 7.2 表达方式

观察式：

“我发现你最近在处理这类问题时，和之前的方式有些不一样。”

联系式：

“这让我想起你之前提到的那个目标，我觉得两件事情之间可能有联系。”

判断式：

“我现在逐渐觉得，你真正关注的可能不是结果本身，而是完成这个结果的过程。”

修正式：

“我之前对你的理解可能不太准确。结合最近的交流，我觉得应该重新看待这件事。”

### 7.3 表达约束

- 必须具有记忆依据。
- 表达强度与置信度匹配。
- 不频繁对用户进行心理分析。
- 不为了展示记忆而机械提及过去。
- 不把阶段性认知包装成永久标签。

系统应记录：

- `last_expressed_at`
- `expression_count`
- `confidence`
- `evidence_refs`

避免重复表达相同判断。



## 8. 主动回顾过去

已确认：允许主动回顾

AI 可以主动回顾以前的共同经历和讨论。

回顾来源包括：

- 当前话题关联。
- 时间节点。
- 过去的重要事件。
- 用户的长期目标。
- 人物关系变化。
- 当前信息与过去记忆之间的联系。

### 8.1 回顾策略

AI 可以想起某件事，但不一定需要说出来。

最终是否表达，由 Dialogue Engine 决定。

### 8.2 回顾约束

- 必须与当前交流存在实际联系。
- 不应在短时间内反复提及同一事件。
- 不要为了证明自己有记忆而强行回忆。
- 对时间和事件依据不明确的内容，不使用确定语气。
- 主动回顾不等于必须开启一个新话题。



## 9. 长期关注主题

已确认：允许自主形成关注

长期关注主题不是普通记忆的附属字段，而是一个独立的数据对象。

### 9.1 两类关注主题

A. 用户相关关注

例如：

- 用户正在推进的项目。
- 用户的学习和职业目标。
- 用户长期关注的问题。
- 用户的重要关系变化。
- 尚未得到结果的事情。

B. AI 自主关注

由 Persona Engine 提供兴趣方向，AI 可以在交流中逐渐形成自己的长期关注主题。

例如：

- 持续感兴趣的技术领域。
- 值得继续讨论的哲学问题。
- 某个反复出现的社会现象。
- 长期探索的知识主题。

### 9.2 关注主题生命周期

关注主题可以具有以下状态：

- Active：持续关注。
- Paused：暂时搁置。
- Completed：已经完成。
- Archived：不再活跃，但保留历史。

### 9.3 数据建议

| 字段               | 说明                |
| ------------------ | ------------------- |
| id                 | 主题 ID             |
| title              | 主题名称            |
| description        | 主题描述            |
| origin_type        | 用户相关 / 人格自主 |
| related_memory_ids | 关联记忆            |
| interest_score     | 关注程度            |
| status             | 当前状态            |
| last_discussed_at  | 最近讨论时间        |
| next_review_at     | 下次评估时间        |

长期关注主题应与 Persona Engine 联动。

需要明确：AI 可以表达自己对某个主题的兴趣，也可以说还想继续讨论，但不能伪造用户不在场时真实发生的生活经历或主观体验。



## 10. 记忆检索机制

采用混合检索。

### 10.1 检索方式

| 检索方式   | 作用                           |
| ---------- | ------------------------------ |
| 语义检索   | 找到意思相关的记忆             |
| 关键词检索 | 找到明确提及的词语             |
| 时间检索   | 找到某个时间段的事件           |
| 关系检索   | 找到人物、事件、目标之间的联系 |
| 上下文检索 | 找到当前话题相关的近期记忆     |

### 10.2 检索优先级

1. 当前会话上下文。
2. 当前话题相关的工作记忆。
3. 相关的重要情景记忆。
4. 相关的长期语义记忆。
5. 其他辅助背景。

### 10.3 检索结果控制

不能将所有记忆一次性塞进模型上下文。

应该根据当前交流需求进行检索，只返回相关内容。

每条检索结果包含：

- 记忆内容。
- 类型。
- 相关度。
- 置信度。
- 来源。
- 时间。
- 有效状态。

当前明确表达优先于历史推断。



## 11. 用户记忆控制权

用户应当具有完整的记忆管理能力。

支持：

- 查看记忆。
- 修改记忆。
- 删除记忆。
- 明确要求记住。
- 明确要求不再记住。
- 质疑 AI 的归纳认知。
- 要求 AI 重新评估某项认知。

删除操作不能只删除主记忆，还应检查并清理：

- 派生认知。
- 相关摘要。
- 向量索引。
- 记忆关联关系。
- 缓存中的相关信息。

涉及敏感信息时，应使用更严格的保存和访问规则。



## 12. 数据模型设计

以下是建议的逻辑数据结构，具体数据库字段可在实现时调整。

### 12.1 conversation_messages

保存原始消息。

```
class ConversationMessage:    id: str    conversation_id: str    speaker: str    content: str    created_at: datetime    metadata: dict
```



### 12.2 memories

保存正式记忆。

```
class Memory:    id: str    memory_type: str    content: str    source_type: str    importance_score: float    stability_score: float    confidence: float    status: str    version: int    valid_from: datetime    valid_to: datetime | None    created_at: datetime    updated_at: datetime
```



### 12.3 memory_sources

保存记忆来源。

```
class MemorySource:    id: str    memory_id: str    message_id: str    source_excerpt: str    contribution_type: str
```



### 12.4 memory_relations

保存记忆之间的关系。

```
class MemoryRelation:    id: str    source_memory_id: str    target_memory_id: str    relation_type: str
```



### 12.5 memory_versions

保存记忆历史版本。

```
class MemoryVersion:    id: str    memory_id: str    version: int    content_snapshot: str    change_reason: str    created_at: datetime
```



### 12.6 working_memories

工作记忆按会话保存，每个会话一行。它不进入 `memories` 的生命周期，也不生成 Embedding。

字段包括 `conversation_id`、`summary`、`current_topic`、`attention_topic_id`、`open_threads`、`expires_at`、`archived_at` 和 `version`。当前用户消息里的即时事实只进入本回合，不写入这张表。

### 12.7 attention_topics

长期关注主题是独立对象，不写进人格版本，也不当作一条普通记忆。

`attention_topics` 保存标题、描述、`origin_type`、状态、`interest_score`、`last_discussed_at` 和 `next_review_at`。`attention_topic_memories` 把主题和作为证据的记忆连起来。人格初始兴趣仍留在人格版本中。





## 13. 核心接口建议

| 接口                           | 功能                   |
| ------------------------------ | ---------------------- |
| `POST /memory/extract`         | 提交消息进行记忆提取   |
| `POST /memory/search`          | 检索相关记忆           |
| `GET /memory/{id}`             | 获取记忆详情           |
| `PATCH /memory/{id}`           | 修正或补充记忆         |
| `DELETE /memory/{id}`          | 删除记忆               |
| `POST /memory/confirm`         | 用户确认或否认归纳认知 |
| `GET /memory/attention-topics` | 获取长期关注主题       |

客户端不直接操作数据库，所有操作通过 Memory Engine 服务层完成。

## 15. 异常处理与降级

| 异常             | 处理方式                 |
| ---------------- | ------------------------ |
| LLM 提取失败     | 保留原始记录，稍后重试   |
| 向量检索不可用   | 降级关键词检索           |
| 记忆冲突无法判断 | 保留候选状态             |
| 检索结果为空     | 仅使用当前会话上下文     |
| 来源缺失         | 降低置信度               |
| 重复任务执行     | 通过幂等标识避免重复写入 |



## 16. 第一版开发范围

建议第一版优先实现：

1. 原始对话记录。
2. 工作记忆摘要。
3. 语义记忆和情景记忆。
4. 异步记忆提取。
5. 基础重要性评分。
6. 记忆来源追踪。
7. 新增、补充、修正和版本管理。
8. 混合检索基础能力。
9. 归纳认知与置信度管理。
10. 主动回顾所需的检索接口。
11. 长期关注主题管理。
12. 用户查看、纠正和删除能力。

暂缓：

- 复杂知识图谱推理。
- 复杂遗忘算法。
- 大规模多模型协作。
- 深层心理画像自动化。



## 17. 验收标准

| 测试场景                 | 预期结果               |
| ------------------------ | ---------------------- |
| 用户明确要求记住某项偏好 | 保存为显式记忆         |
| 用户偶尔表达一次不满     | 不直接形成长期认知     |
| 用户多次表达相似偏好     | 稳定性逐渐提高         |
| 用户改变偏好             | 创建新版本，保留历史   |
| 同一消息重复处理         | 不产生重复记忆         |
| 用户询问过去的决定       | 能够找到相关事件和来源 |
| 当前话题关联过去经历     | 能够自然回顾           |
| 用户否认某项认知         | 重新评估或修正         |
| 用户删除某项记忆         | 同步清理相关派生信息   |
| 检索不到历史依据         | 不得伪装成记得         |
