# AI Companion · Midnight 夜猫主题前端构建规范 V1.0

日期：2026-11-27  
适用范围：移动端首页、聊天、设置、登录及桌面端移动布局复用。

## 1. 构建目标

在现有 AI Companion 前端上新增可切换主题 `midnight`，完整还原已确认的无玫瑰夜猫定稿。原云朵主题继续可用。主题仅影响视觉资源、样式和表现动画，不重建用户体系、伴侣实例、聊天记录、人格、记忆或决策引擎。

采用 Vue 3 + TypeScript，复用现有路由、组件、状态管理和后端通信。先检查项目实际目录、API、事件协议和主题实现，再对接，不凭空新增另一套业务接口。

## 3. 主题视觉规范

设计逻辑尺寸 440×956 CSS px，3x 导出 1320×2868。设计坐标是还原基准，不是固定设备高度。建议主题 token 如下，实际以定稿对照微调。

| Token | 值 | 用途 |
|---|---|---|
| --theme-bg | #090408 | 全局底色 |
| --theme-surface | #190B12 | 卡片、输入框底色 |
| --theme-surface-raised | #291019 | 伴侣消息 |
| --theme-primary | #A81942 | 用户消息、主按钮 |
| --theme-accent | #F04A7C | 选中图标、关键高光 |
| --theme-text | #F5E6D8 | 主文字 |
| --theme-text-muted | #B79896 | 次文字、占位文字 |
| --theme-border | rgba(183,69,101,.30) | 描边 |
| --theme-glow | rgba(232,50,105,.28) | 局部光晕 |

主色保持低亮度黑红与酒红，猫瞳、月牙、星芒和主按钮可高亮。不要引入玫瑰、叶子、蓝色科技光、满屏霓虹。标题可用系统宋体或已授权中文衬线字体，聊天正文优先使用清晰的系统中文字体。正文 15–17px、辅助 12–14px、标题 22–28px。圆角 12–18px，常规页面水平间距 20–24px。

## 4. 页面布局与交互

以下为 440px 基准宽度的推荐布局，优先参照定稿，在安全区和窄屏上重新排版。

| 页面 | 背景 | 核心组成 |
|---|---|---|
| 首页 | home | 时间、主题标题、全身角色、当前状态、底部导航 |
| 聊天 | chat | 居中动态头像及伴侣名称、消息列表、输入栏、底部导航 |
| 设置 | settings | 标题、主题/记忆/关于/账户四类入口、底部导航 |
| 登录 | login | 月光场景、黑猫、标题、账号密码、登录按钮 |

### 4.1 首页

- 顶部保留时间和主题标题，时间取设备实际时间；系统已有状态栏时不重复绘制。
- 角色 stage 宽度 min(100%, 440px)，高度与宽度保持一致，按底部中心锚定绒面区域；使用 object-fit: contain。
- 初始参考位置：角色可视区域约 y=180–690，当前状态约 y=745–785，底部导航约 y=850 之后。随可用高度调整，不与状态文字和导航重叠。
- 当前状态来自服务端伴侣状态；没有状态时显示中性的待机文案。
- 角色默认静态、按状态更新；支持已确认的局部眨眼和摆尾，不加整图缩放、呼吸或后背起伏。
- 星芒使用独立图层，分散于四周，不盖住文字和交互区域。

### 4.2 聊天页

- 头部头像和名称整体居中，头像负责回复中、思考中或情绪变化等动态反馈。
- 消息列表独立滚动，伴侣左侧、用户右侧；气泡最大宽度约 78%，允许长文换行；消息使用真实数据库记录。
- 顶部头像可使用状态头像，历史气泡内的小头像默认使用 default，不要求随当前情绪变化。
- 输入栏常驻底部，键盘弹起时随可视区域上移，发送按钮有 disabled、sending、失败重试状态。
- 复用现有 SSE 与聊天逻辑。流式新增消息时仅在用户位于列表底部或主动发送时自动跟随；用户向上阅读历史时不强行拉回。
- 不在会话消息额外插入情绪状态卡片；Quiet 等行为不伪造回复。

### 4.3 设置页

- 复用主题、记忆、关于、账户入口，标题和图标与定稿一致。
- 主题可切换云朵和夜猫，当前选择保存到本地用户偏好；登录用户若现有后端支持同步则沿用。
- 记忆只读展示，不能新增删改入口；伴侣内部状态不可通过视觉设置直接调整。
- 账户和关于走现有功能，退出登录遵循现有账户流程。

### 4.4 登录页

- 黑猫角色和月光背景分离，角色可采用 curious 或 idle 素材。顶部图形约占可用高度 42%，中部标题，下面为表单。
- 按实际认证接口展示账号类型和密码字段；不要虚构短信、注册、找回密码接口。
- 登录按钮防重复提交，保持错误反馈可读。已登录使用现有路由守卫跳转。
- 键盘弹出时表单可滚动，背景仍覆盖可视区域。

## 5. 公共层级与适配

背景 z-index 0；氛围装饰 1；角色 2；正文与交互 10；导航 20；弹层 50。装饰 pointer-events: none、aria-hidden=true。

- 使用 CSS px、百分比、clamp、flex/grid，按宽度自适应；不要全页面 transform: scale()。
- 可用高度采用 100dvh，提供 100vh 兼容；safe-area-inset-top/bottom 接入现有安全区处理，避免两次叠加。
- 推荐验证 360×800、390×844、440×956，以及桌面窗口中的移动布局。小屏优先保证表单、聊天框和底部导航可用。
- 背景以 center center / cover 实现，可按不同页面微调 background-position；人物采用 contain，禁止裁切耳朵和尾巴。
- 项目真实状态栏、键盘区域与导航高度优先，不把截图中的时间、电池、信号图标烘焙成 UI。

## 6. 角色状态及动画

| UI 状态 | 文件键 | 触发语义 |
|---|---|---|
| 默认 | idle | 无明确状态 |
| 开心 | happy | 积极情绪 |
| 害羞 | shy | 害羞或局促 |
| 好奇 | curious | 好奇或注意 |
| 生气 | angry | 不悦 |
| 失落 | sad | 低落 |
| 睡眠 | sleeping | 休息 |
| 亲昵 | affectionate | 亲昵表达 |

只对接现有后端真实情绪/状态字段，前端增加映射适配层。未知状态、无值默认 idle；不要通过关键词或随机逻辑更改伴侣真实情绪，不添加好感度。

```ts
export type CompanionVisualState =
  | 'idle' | 'happy' | 'shy' | 'curious'
  | 'angry' | 'sad' | 'sleeping' | 'affectionate'

export const visualStates = [
  'idle', 'happy', 'shy', 'curious',
  'angry', 'sad', 'sleeping', 'affectionate'
] as const

export function normalizeVisualState(value: unknown): CompanionVisualState {
  return visualStates.includes(value as CompanionVisualState)
    ? value as CompanionVisualState
    : 'idle'
}
```

先依据实际后端枚举映射到上述 UI 键，再调用归一化函数。

### 6.1 动画接入决议

已确认动画对应 curious 坐姿，72 张 480×480 透明 PNG，约 4 秒一轮，原序列 56ms/帧。GIF 预览为 60ms/帧，约 4.32 秒；GIF 透明通道和颜色精度有限。生产首选透明 APNG（preview.png，可重命名为 curious.apng 并配置正确 MIME），或使用原始序列配合 Canvas。优先验证实际目标运行环境的 APNG 支持与资源大小。

- 仅 curious 使用该动画，其余七态先用静态资源，不能把同一动画冒充其他状态。
- 静态图和序列的实际内部人物定位可能略有出入，接入时以首帧为 curious 静态回退，避免切换时跳位。
- 动画只有眨眼、局部摆尾，固定身体和后背；不增加全身 scale、呼吸动效。
- 动画结束、换状态或组件卸载时取消计时及渲染。隐藏页面、低性能或 reduced-motion 下使用静态图。
- Canvas 方案在切换状态前预加载帧，用 requestAnimationFrame 的实际经过时间计算帧号；切换时以当前资源加载标识防止旧回调覆盖新状态。
- 两套角色素材同时存在时，只显示当前状态的有效资源，加载失败回退同状态静态图，最终回退 idle。

### 6.2 氛围动效

星芒使用 opacity 0.15–0.9 的低频缓入缓出，周期建议 2.5–6 秒并错开延时，保持点光源锐利。首页/登录可放置约 6–10 个，聊天/设置约 3–6 个。月牙吊坠光效可独立叠加，但当前角色素材没有单独吊坠图层，第一版不强制制作。禁止高频闪屏和大面积泛光。

## 7. 主题架构与持久化

- 主题标识建议 `cloud`（沿用实际既有标识）与 `midnight`，在既有主题注册表中新增 midnight。
- 用应用根节点 data-theme 或现有机制挂载 CSS token；角色、背景、头像通过主题资源表解析，不将黑猫资源路径硬编码在通用页面。
- 现有用户偏好优先，按用户 ID 隔离持久化，匿名与登录后的偏好合并遵循现有规则。
- 切换主题时保留消息列表、输入草稿、会话 ID、伴侣 ID 以及已连接的业务状态；不重新创建伴侣。
- 使用静态资源 import 或明确资源映射，避免生产构建后动态拼接路径无法解析；仅加载当前主题在当前页面需要的资源。

## 8. 开发与验收

按照「检查现有工程 → 注册主题及 token → 资源映射 → 四页还原 → 状态及动画 → 账户/会话联调 → 视觉与性能验收」的顺序实施。

### 必须通过的验收项

- [ ] 440×956 基准下逐页对照原定稿；使用纯背景叠加真实组件，无玫瑰，无整页截图充当 UI。
- [ ] 360 与 390 宽设备、桌面移动窗口下无横向滚动及控件重叠；键盘展开可输入发送。
- [ ] 八种状态素材完全切换，角色基线一致，耳朵尾巴完整；curious 动画循环时后背稳定且背景透明。
- [ ] 图标、星芒无明显矩形底板；若原切图存在残留像素，局部清理或使用同风格矢量图标并经视觉对照。
- [ ] 主题切换后聊天记录、草稿、当前用户、伴侣人格与记忆保持一致。
- [ ] 聊天 SSE、失败重试、滚动及 Quiet 行为符合现有协议；记忆只读，状态不可手动调整。
- [ ] 登录成功、失败、重复提交防护、退出及路由守卫可用。
- [ ] 生产构建无资源路径 404，无临时调试文件，不打包参考图与未使用帧；移动端页面离开后无动画定时器泄漏。
- [ ] 对照现有云朵主题进行回归，确认主题切换不会改变其视觉或业务逻辑。
