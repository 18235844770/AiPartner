# 对话质量问题与升级记录

日期：2026-11-06

样本：陪伴者「艺」（INFP），会话 `c27df6f8-e4f8-4e8d-a827-296ccbe85c59`，最后一轮用户问「你平时会喜欢看电影吗？」。

## 已经确认的问题

### P0 身份与人格缺失

- 决策和表达的系统提示都没有陪伴者身份，只规定输出格式和几条禁令。
- 人格没有单独的提示。决策用户消息里只有 MBTI 和两句摘要，表达阶段连这些都没有。
- 七轮决策动机按客服来写。从第四轮起，理由直接把说话者写成「助手」。
- 初始人格没有形成可引用的个人认知，行为特质是空对象。

### P0 决策缺少自身动机

- 决策只选择 `respond`、`share`、`ask`、`react`、`continue`、`close`、`quiet` 之一。
- 提示没有要求先回答「我自己对当前内容有什么兴趣、观点和表达欲望」。
- 七轮全部发送。动机都是礼貌回应、共情再追问、猜测或分享偏好再反问，形成 Share + Ask 的通用模板。

### P1 初始人格与记忆不足

- 六种 MBTI 模板只有标题、一句性格摘要和一句表达摘要。
- 没有自我身份、个人背景、具体兴趣、独立观点、价值倾向、思维习惯和个人关注。
- 当时已有三条候选记忆，包括下午看过爱情恐怖片。问电影时检索结果是空的：记忆正文没有「电影」，向量也没有命中。

### P1 上下文传递不完整

- 表达请求只有已通过的决策、记忆、当前句子和最近 10 条对话。
- 人格、状态和工作记忆没有进入写正文的请求。
- 决策里的「助手坦诚分享自己的观影偏好」成了写作要求，于是回复编出观影习惯，并猜了《倩女幽魂》。
- 「不要编造经历」写在提示里，生成后没有再检查。

### P2 模型与参数配置，待验证

- 两个模型的 `parameters` 都是空对象，请求里没有温度、`max_tokens` 或 thinking。
- 决策模型 `deepseek-v4-pro`，表达模型 `deepseek-flash`。
- 决策输出 1556 token，落库 JSON 很短。原始响应没有保存，多出来的 token 当时无法核对。
- 调用日志不保存提示和原文，决策调用也没有关联到 `dialogue_decision_id`。

## 当时的回放不是真实请求

那一次排查是用当时的代码和数据库重新组装的，不是模型收到的原始请求。无法确认的有：

- 工作记忆原文。那一行后来被改写。
- 实际使用的人格版本是否与回放时一致。回放时版本仍是 1，但不能代替原始请求。
- 完整系统提示和最终发出的 messages。
- 模型返回的完整推理和响应。
- 供应商在空参数下实际采用的默认参数。

因此可以确定架构缺陷，还不能把每一句低质量回复精确归因到某一个字段。

## 这次采用的升级

继续 Persona Engine V1.0 已确认的初始方案：六种人格等概率、只在创建时抽取一次、核心 MBTI 不因普通对话改变、变化保留版本和原因。不新造一套人格分类。

个人背景写成这个陪伴者如何理解自己，不写成用户不在场时发生过的生活经历。兴趣和观点是稳定倾向，不是声称发生过的事件。

### 人格档案

`persona_versions.archive` 保存八项，并有数据库约束：

- 自我身份定义 `identity`
- 个人背景 `background`
- 兴趣偏好 `interests`
- 独立观点 `viewpoints`
- 价值倾向 `values`
- 思维习惯 `thinking_habits`
- 交流倾向 `communication`
- 个人关注 `attention`

新建陪伴者从模板写入完整档案。已有版本按 MBTI 回填这八项，原有核心特质字段保留。

### 自主动机、Policy 和 Capabilities

决策必须同时写出 `user_need` 和 `self_motivation`。后者包含兴趣、观点和表达欲望。

Dialogue Policy 与 Dialogue Capabilities 放在数据文件里，进入决策系统提示。它们约束现有七种行为，不增加行为种类。Policy 包括对话平衡、话题延续、主动分享、提问控制和助手化抑制。

模型若在动机或理由里把自己写成助手，结构校验不通过，并走原有的一次修复。明确写出「不是助手」不算违规。

### 上下文组装

决策和表达由同一个组装器供数，粒度不同：

| 上下文 | 决策 | 表达 |
| --- | --- | --- |
| 身份定义和个人背景 | 必须 | 必须 |
| 核心人格，含价值和思维习惯 | 必须 | 必须 |
| 兴趣、观点、个人关注 | 与当前内容相关，或对方在问自己时 | 与本次表达相关时 |
| 初始记忆 | 检索结果中来源为 `system_generated` 的条目 | 相关时 |
| 后天记忆 | 本轮检索结果 | 相关时 |
| 情绪与关系状态 | 必须 | 必须 |
| 工作记忆 | 必须带全文 | 只带相关摘要 |
| 交流决策 | 本阶段生成 | 必须，连同自身动机 |

### 可回放的调用日志

开发环境默认保存脱敏后的完整快照：系统提示、完整 messages、实际发出的参数、返回的模型标识、原始响应、token、上下文版本。密钥和 `sk-` 开头的字符串会先去掉。

快照默认保留 14 天，过期后只清正文，调用元数据仍在。列表接口不返回正文。快照只在开发环境、或显式打开 `MODEL_LOG_EXPOSE_SNAPSHOTS` 时，经陪伴者归属校验后读取。

正式环境默认不采样正文。可用 `MODEL_LOG_DETAIL`（`full`、`redacted`、`off`）和 `MODEL_LOG_SAMPLE_RATE` 改变。`redacted` 保留结构，正文换成长度标记。

决策保存后，把同一 `trace_id` 上尚未关联的调用补上 `dialogue_decision_id`。表达调用在发出前就带上这个决策。

Embedding 保存输入文本和向量数量、维度，不保存向量本身。

## 仍待验证

空参数时供应商的默认温度和 thinking 仍要靠新的原始响应来确认。这次升级保证以后能看见它们，但不改模型配置里的参数值。
