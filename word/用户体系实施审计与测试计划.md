# 用户体系 V1.0 实施审计与测试计划

## 现状与复用

| 模块 | 已有实现 | 本次差异 |
|---|---|---|
| Identity | `users`、`companions`、伴侣归属查询、桌面端工作区 | 增加登录凭据、设备会话、认证及账号生命周期。现有用户只有显示名。 |
| Persona、State | 随机模板、人格历史版本、初始化状态和状态事件 | 复用初始化逻辑，改由服务端组织，按账号幂等。当前模板初始化不调用外部模型。 |
| Conversation | `0018` 限制每伴侣一条活跃会话，复合外键校验归属，行锁分配消息序号，客户端消息 ID 去重 | 绑定唯一长期会话，补充游标和幂等冲突检查，保留旧会话归档。 |
| Dialogue | 决策、Quiet、多消息回复、按回合输出 SSE | 持久化回合状态、失败回合重试、可恢复的账户级事件订阅。 |
| Memory | pgvector、工作记忆、关注主题，已有多处伴侣维度查询 | 核查所有检索、更新、任务和调试 API 的账号隔离。 |
| Infrastructure | PostgreSQL 任务表、ARQ、调度进程、按任务的锁和主动评估定时器 | 同伴侣的用户回合和主动回合统一串行，完善到期扫描、预算、停用及失败恢复。 |
| Audio | 按消息合成、流式语音和按归属下载资产 | 媒体访问绑定可信账号，验证音频失败不会影响文本及同步。 |
| 客户端 | Electron 工作区创建和静态移动端稿 | 增加移动 Web 四页和认证会话管理，核对旧桌面接口的本地兼容。 |

`0018_one_active_conversation` 是审阅时的仓库迁移头。生产库版本、历史数据规模、重复绑定和备份恢复能力需要在上线环境核对。工作区已有对话模块的未提交改动，后续接入以实际工作树为基础。

## 迁移与发布顺序

1. 先扩展账号字段、会话表和数据库约束。既有 `users.id` 保留，登录字段允许为空，未认领的旧用户继续作为实验工作区数据存在。
2. 为新账号建立服务端唯一伴侣及长期会话。针对确认归属的旧数据，逐账号记录匹配结果、有效伴侣和长期会话，先校验再回填。归属不明确的数据保持隔离。
3. 多用户部署仅暴露认证后的产品接口。原本供 Electron 本地调试的操作须由本地模式保留，检查直接通过旧路由访问历史、认知、日志和任务的边界。
4. 用备份副本验证升级和恢复，核对各表数量、归属、序号、向量及音频引用，再切换流量。破坏性降级依赖已验证的备份恢复。

## 自动化测试计划

- 账号测试覆盖归一化唯一性、密码与令牌脱敏、登录限流、并发刷新、单设备退出和改密撤销。
- 初始化及迁移测试覆盖并发双注册、同账号重复初始化、中断重试、旧用户继续存在、旧会话和消息归属校验。
- 会话测试覆盖重复发送、不同内容冲突、失败重试、Quiet、多条回复顺序、分页和重启恢复。
- 隔离测试使用两个用户，对历史、记忆、pgvector、媒体、事件、后台任务和调试接口逐一验证。
- 调度和客户端联调用例覆盖主动与用户消息竞争、多设备断线、退出后迟到事件、注销清理和语音失败。
- 在相同模型及部署环境下采集改造前后的首字、完整回复和 TTS 首包时间及 P50/P95，同时运行认知模块回归测试。

## 本轮实现与复核

| 迁移 | 变更 |
|---|---|
| `0019_account_sessions` | 账号凭据、设备会话、初始化状态和长期会话标识 |
| `0020_account_chat` | 接收消息时一并写入可重试的聊天回合 |
| `0021_companion_review` | 按伴侣持久化下次主动评估时间 |
| `0022_account_erasure` | 按外键依赖顺序清理账号数据 |

面向移动端的入口为 `/mobile/`。认证使用同源安全 Cookie。账号 API 包含注册、登录、刷新和退出，个人资料与密码更新、注销，伴侣初始化状态与重试，聊天历史与提交、回合重试、SSE 和私有语音。服务端用 `ACCOUNT_MODE=true` 启用账号模式，API 和 ARQ 进程使用相同配置。

本地隔离环境已执行 Alembic 升级、PostgreSQL 备份和独立数据库恢复。实际生产库的数据归属、保留期限、真实模型和 TTS 延迟、跨环境部署及线上并发量仍需在对应环境验收。旧用户和实验数据保留原 ID，账号体系没有自动认领这些数据。

本地全量后端测试通过 216 项，1 项音频表达断言失败。仓库原有音量实现为 `1.25`，原有测试要求 `>= 1.5`。账号集成测试通过，覆盖并发注册、双账号隔离、发送幂等、模型超时后的回合重试、SSE 历史补齐、文本与 TTS 故障解耦及注销清理。Edge 移动视口测试通过注册、发送、刷新恢复历史、更新资料和注销。
